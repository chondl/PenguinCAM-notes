## Defects

Most serious first. "Carried over" means the print branch behaves the same way.

1. **A good slice is thrown away when Orca's side files have an unexpected shape.**
   Carried over. `slicer.read_summary` lines 273 to 282 catch only `ValueError` and
   `OSError` while reading warnings, so a `result.json` that is a list, or whose
   `sliced_plates` holds a non-object, raises `AttributeError` after Orca has sliced
   successfully; the sliced file is deleted with the scratch folder and the caller gets
   `slice.unexpected` (probes D, D2). `contracts/sliced-file.md` says a number Orca did not
   report is null, not a failure. Related: a null `bbox_objects` (probe G) and a corrupt
   entry in a readable zip (probe O) also end as `slice.unexpected` instead of
   `slice.unreadable_output`. Fixed when: warnings of any JSON shape give an empty list
   and the sliced file is delivered; G and O give `slice.unreadable_output`; a test for
   each.
2. **Success is reported with a path that is not the sliced file.** Made by the port.
   `service.slice_plate_job` line 188 uses `shutil.move`; when `<out>/<name>` exists as a
   folder the file lands inside it and `SlicedFile.path` is the folder (probe H). Fixed
   when: `SlicedFile.path` is always the file itself, or the call fails with an error
   report, with a test.
3. **Orca's return code -100 gives an untrue sentence, a remedy that contradicts it, and
   a detail without the reason.** Sentence carried over; code, remedy and action made by
   the port. Evidence: the real Orca run under check 4. The part had a flat face on the
   plate, the sentence says to choose another face, the remedy says to turn supports on,
   and `result.json`'s `error_string` is never read, so it is destroyed with the scratch
   folder (the contract: detail is captured before cleanup removes its source).
   `contracts/examples/error-report.json` shows a `slice.empty_layers` report with a
   copy, a height and Orca's own words; the slice service cannot produce any of the three.
   From my memory of Orca's source, -100 is its general slicing error and not only empty
   layers; I did not verify that here. Fixed when: the detail holds `error_string`; the
   sentence and remedy agree and are true for the gap part; the contract's example is one
   the slice service can produce; a real-Orca test produces -100.
4. **Four codes have a blank detail though evidence exists.** Made by the port
   (`errors.error_report`, the `MeshError` and `OverrideError` branches, and the
   exceptions themselves, which carry no detail). `slice.part_unreadable` covers three causes (not
   binary, wrong length, non-finite coordinates) and reports none; `slice.part_too_detailed`
   omits the size or triangle count; `slice.part_too_small` omits the extent;
   `slice.bad_overrides` omits which override (probes P, S). `test_detail_carries_the_evidence`
   leaves eight codes out of its list, these four among them. Fixed when: each carries the measured value
   and the file, and the test covers all 28 codes.
5. **Orca killed by a signal is reported as a fault of the part.** Carried over in the
   sentence; the code and remedy are the port's. A return status of -9 (the kernel's
   answer to running out of memory, the tight resource here) gives `slice.orca_failed`,
   "The slicer could not process this part.", "Try another orientation or other print
   settings", not retryable (probe E). Fixed when: a negative status has its own code,
   says the server stopped the slicer, and is retryable, with a test.
6. **A plate job value Python cannot convert is reported as a server bug.** Made by the
   port. `service._is_number` calls `math.isfinite` on any integer; 10^400 raises
   `OverflowError`, reported as `slice.unexpected` (probe A). Fixed when: it is
   `slice.bad_plate_job`, with a test.
7. **File system failures are reported as "The slicer failed unexpectedly. Slice again".**
   Made by the port. An output folder that cannot be made (B), an STL that cannot be read
   (C), an STL that vanishes between the check and the plate writer (Q): each is
   `slice.unexpected` with a remedy that cannot help. Fixed when: each has a true sentence
   and remedy, with a test.
8. **Orca output that is not UTF-8 fails the slice.** Carried over. `_run_orca` runs with
   `text=True` and strict decoding (probe F). Fixed when: undecodable bytes are replaced,
   with a test.
9. **The remedy, action and retryable flag of every code are untested, and two codes are
   produced by the test itself.** Made by the port. `test_failure_produces_its_code`
   compares the report with `CODES`, the table the report was built from; mutations m06
   and m07 pass all 420 tests. `slice.job_failed` is produced by the test raising
   `JobFailure`, which no code in the package raises; `slice.unexpected` by the test
   evaluating `1/0`. The guide says the tests produce each code "on purpose" and the test
   module says "by the code that really raises it". Fixed when: the expected remedy,
   action and flag are written in the test; `slice.unexpected` is produced through
   `slice_plate_job`; `slice.job_failed` is either reachable or removed.
10. **Nothing tests that a failed job wakes a waiting subscriber.** Made by the port's
    test rewrite (the code is carried over). Mutation m11 makes a failed job skip the
    notification; all tests pass, because every failure test finishes the job before
    anyone waits. A subscriber would hang until its timeout. Fixed when: a test has a
    subscriber waiting with no timeout while the worker fails.
11. **The type of an override value is untested.** Made by the port's test rewrite.
    Mutation m14 removes the type comparison in `print_config._choice`; all tests pass.
    With it removed, `infill` 20.0 would be written to Orca as `20.0%`. Fixed when: a test
    refuses 20.0 for `infill` and 3.0 for `walls`.
12. **The Orca version is stated in six files and knowledge of Orca's files in four
    modules.** Made by the port. The version: `scripts/install-orca.sh` 15 (the pin),
    `tests_orca/test_orca.py` 38, `tests/test_print_config.py` 85,
    `tests/test_install_orca.py` (five places), `contracts/sliced-file.md` 4,
    `slice/README.md` 50. The return codes are in `slicer.ORCA_CODE_MESSAGES` and again in
    `errors._ORCA_CODES`. Orca's output is read in `slicer.read_summary` and in
    `plate_3mf.plate_object_names`; Orca's setting names are in `print_config.py`. The
    review brief counts both as defects in this phase because they make an upgrade
    harder. Fixed when: tests read the version from the pin, and one module holds the
    return codes and reads everything Orca writes.
13. **Two make targets do not do what the guide says.** Made by the port. `test-flakes`
    uses seeds 1 to 10 every time, so it re-runs the same ten orders and can never find an
    order outside them. `test-parallel` uses four workers; the standing rules allow two on
    this machine. Fixed when: `test-flakes` draws new seeds and prints them, and the
    worker count is two or a variable.
14. **Sentences that are untrue outside the earlier application.** Carried over, and the
    guide says so. "Onshape could not export Box. Try again, or Refresh from Onshape." for
    any unreadable STL, "A part is no longer on the server; press Refresh from Onshape on
    the Parts step." for a `ref` typo, "The team configuration names printer ..., which
    PenguinCAM does not know. Ask a mentor to fix printing.printer." for an unknown
    printer (probes R, S, T). The slice service's guide says it knows nothing of Onshape
    or teams. "A part was left off the plate" has no full stop. Fixed when: every sentence
    is true for a plate job from any source.

## Not defects in this phase, for the hardening brief

- The job queue's record carries the failure as one sentence, not an error report, and
  has no `cancelled` state, no `sequence` and no progress; the service does not use it.
- `make coverage` has no threshold, so a drop fails nothing.
- A terminated service process leaves its scratch folder and can leave Orca running
  (`finally` does not run on SIGTERM).
- On a timeout only Orca's stdout is kept; stderr is dropped.
